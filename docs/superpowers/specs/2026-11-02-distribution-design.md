# Zotero PDF2zh Easy 分发版设计

日期：2026-11-02。用户已确认：跨 Windows、macOS、Linux；小体积 XPI 加首次引导安装；以下整体设计。

## 目标和边界

将现有 PDF2zh 4.1.8 本机增强方案整理为可构建、可分享的独立发行版本。保留双语全文翻译、附件导入、实时进度、自动准备服务与服务恢复。修复普通启动及翻译入口的终端闪窗，替换存在黑边的独立进度窗口。不得发布个人凭据、文献、日志、机器路径或虚拟环境。Windows 实机验收，macOS/Linux 提供实现与可用的自动测试，但明确未实机验证，不宣称已全面兼容。

## 架构与隔离

插件负责 Zotero 集成、设置界面、进度卡片和引擎管理。受控本地辅助程序负责安装及启动、就绪检查、单实例互斥、状态和脱敏诊断。翻译后端基于现有上游服务及必要兼容补丁，保留许可证和来源。公开仓库必须包含可构建源码与固定依赖版本，不能只提交打包的编译脚本。

使用独立发行名称和插件标识；检测原版冲突并引导关闭原版，避免重复菜单、重复任务和双重启动。现有用户配置仅本地经明确迁移保存，绝不写入发行默认值。不得静默覆盖原版配置或删除用户安装。

## 安装与运行

XPI 不包含大体积 Python 环境。设置页首次点击“安装翻译引擎”时明确说明网络下载、磁盘占用及本地执行；无需管理员权限，不修改系统 Python。运行环境安装到当前用户独立数据目录，不引用开发机的盘符和用户名。固定受信下载来源和版本，验证可得的校验信息；不执行任意用户输入拼成的 shell。安装有进度、失败状态和重试入口，防止并行重复安装，未完成环境不得标记为可用。

引擎安装完成后，Zotero 启动时异步准备服务；翻译前等待就绪并恢复已退出服务。全部子进程链均须审核后台标志，不能只隐藏最外层进程。服务仅绑定回环地址；不因发现某端口返回健康响应便盲目提交文献或密钥，应验证受管理服务身份。超时有界，避免重复启动。保留服务在 Zotero 关闭后运行的现有行为，以免打断任务，不添加系统登录启动项。

本机闪窗根因须先通过进程链与窗口观察验证，不能仅凭截图或已有注释判定已修复。当前代码已使用 pythonw 和部分 CREATE_NO_WINDOW，仍须检查 venv 启动器与所有后代进程。

## 进度界面

使用 Zotero 主窗口内部的左下角卡片，不再以独立原生 progressWindow 作为此插件翻译的常规进度载体。避免全局 ProgressWindowSet 和其他插件相互影响。卡片显示批次总进度、当前阶段、文件名和完成/失败数量，长文件名省略且有完整提示；可折叠，完成后自动收起，错误可查看。多任务共享一个受控容器，不创建叠加的原生窗口。适配深浅主题及窗口缩放，不遮住主要操作；卸载和关闭窗口清理监听与 DOM。

## 设置界面

四个区域：翻译服务、引擎安装、翻译选项、诊断。

- 服务：OpenAI 兼容 API base URL、遮罩密钥、模型、连接测试；验证 URL 和必填字段，避免输出包含密钥的错误。远程提供商请求前明确其会收到待翻译文本。
- 安装：安装/修复引擎、准备中/就绪/失败状态及下载进度。
- 选项：语言、双语布局、并发/QPS 与现有质量选项；保留现有能力，不另造与后端不一致的配置项。
- 诊断：服务状态与脱敏错误，可获取不含凭据及文献内容的诊断信息。

本机继续使用用户当前模型 deepseek-flash、并发 128/QPS 48、reasoning_effort=none、关闭自动术语表及现有布局/缓存设置。新用户不预填个人 API 地址、密钥或模型；采用保守并发默认值，128/48 作为明确可选高并发预设，说明限流风险，不宣称适用于所有提供商。

## 发布

计划在实际 GitHub MCP 授权用户账号创建公开仓库 zotero-pdf2zh-easy。邮箱只作用户提供的标识，必须核对授权用户名。用户已授权创建及上传，但实际执行前仍需验证目标与内容。保留上游署名和许可证，补充修改说明、依赖来源和许可证要求。提供源码、构建/测试命令、中文 README、安装使用/卸载/恢复说明、XPI 产物和平台验证矩阵。更新源不得沿用会覆盖增强版的原版发行地址。推送前审核文件清单和秘密扫描结果；本机配置和文献不进入版本控制。

## 验收标准

1. Windows 实测普通方式冷启动以及翻译入口恢复服务，全程无终端窗口；通过窗口/进程观察记录证据，不仅以启动参数推断。
2. 实际翻译一页合成测试文档，进度持续更新、无黑边或空白原生窗口、结果可读且在 Zotero 可打开；不使用用户文献作为公开测试样本。
3. 隔离的干净用户数据目录验证首次引导安装、重复点击、安装失败恢复及再次启动，不能只复用开发环境便宣称安装成功。
4. 本机配置迁移前后非敏感字段比对，凭据只验证保留不打印；原版禁用/冲突处理有明确恢复路径。
5. 自动测试覆盖配置验证、路径转义、并发安装/启动、就绪超时和身份检查、进度生命周期、打包白名单与秘密排除。
6. Windows 实机验证与 macOS/Linux 未实机验证状态写入 README；不生成或宣称不存在的跨平台实测。
7. GitHub 仓库确实存在，远程源码与本地审查版本一致，构建入口及可下载安装产物实际检查成功。

## 风险与实施顺序

先完成源码与许可核对、回归基线和闪窗/黑边调查，再实现后台进程和内嵌卡片；随后实现跨平台引导安装及设置；最后隔离安装验证、本机迁移和 GitHub 发布。操作本机前确认无运行中的翻译；不随意停止 Zotero 或抢焦点。使用备份和可回退安装，不删除旧项目。跨平台引擎依赖下载、架构支持和网络失败属于显式错误路径，不得用未经验证的“支持所有系统”承诺代替。

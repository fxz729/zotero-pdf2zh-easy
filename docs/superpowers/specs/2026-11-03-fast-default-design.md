# v0.1.1 高吞吐默认与效果预览设计

## 用户确认

用户明确要求发行默认与本机一样，并通过本会话选择“按此方案直接完成”：新安装默认 128 并发 / 48 QPS，保留 8/4 保守预设，升级不覆盖已有设置，不改翻译引擎和高级质量参数；加入三张效果图与性能说明，测试后发布 v0.1.1，保留 v0.1.0。

## 方案与取舍

不采用覆盖所有升级用户参数的方案，因为会破坏已有配额和设置；不继续以 8/4 为新用户默认，因为违背本次明确要求。采用仅修改 Zotero 默认偏好分支及空值显示回退的最小方案，普通设置页仍选择“保持当前设置”。Next 的 poolSize=128、qps=48；旧引擎 threadNum 保持原值。醒目说明 API 配额、费用与 429 风险，并保留显式 8/4 回退。

## 版本与资源

插件版本升到 0.1.1，依赖锁只修改根包版本，不升级依赖。运行环境版本继续 0.1.0；25 个受管运行时源文件不改，避免无必要重装。发布审计分别验证插件与运行时版本。保留原 0.1.0 Release 和原生证据，不把旧验收当作新包重测。

三张用户明确要求公开的截图按原顺序存入 docs/images，检查真实文件 SHA256、格式、尺寸后仅保存干净 PNG，不附原论文 PDF。首页展示正文、框架图、表格，并保留论文署名/版权提示。仅从截图说明展示内容，不能据此宣称通用翻译准确率或计时结果。

## 验证与边界

先改默认值/显示/版本审计回归，观察旧实现失败，再最小实现。验证保守预设和已有设置不被写入；运行全量 Node/Python、类型检查、构建及 XPI 审计。检查图片可解码、Markdown 路径有效、新包默认值及更新 feed；公开下载后逐字节核验。不开 Zotero、不修改本机 API、偏好或受管环境，不再次付费翻译。macOS/Linux 仍未实机验证，远程 CI 状态如实记录。
